# Define the next milestone and its completion criteria

Type: grilling
Status: open
Blocked by: 08, 09, 11
Parent: [Game-tracker planning map](../map.md)

## Question

With feature priorities and visual direction agreed, what is the smallest
coherent next milestone, what is explicitly deferred, and what observable
criteria let the owner accept it and move toward inviting testers?

## Discussion requirements

- Name the milestone and its user outcome; list must-haves and deliberate cuts.
- Account for the requested critic ratings using the rating-source research.
  Distinguish a preferred provider from verified access and agree a fallback or
  explicit prerequisite before promising display or catalog-wide score sorting.
- Agree a scope or effort boundary with the owner; do not invent a deadline.
- Define representative owner-review journeys at desktop and phone widths,
  including the selected improvement and the accepted save/status/library flow.
- Carry forward private-account boundaries, data preservation, accessibility,
  and the accepted HTTP/PostgreSQL and browser verification seams.
- Distinguish product milestone acceptance from the remaining host selection,
  HTTPS/Tailscale configuration, and remote-phone deployment checks needed
  before invitations. Do not silently add operator execution to this milestone.
- End with a planning handoff for a follow-up specification. Do not modify the
  completed build specification to imply that new work was already accepted,
  create implementation tickets, implement features, or invite testers here.
